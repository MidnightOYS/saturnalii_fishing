# «Гнев глубин» · ТЗ на растровые макеты и игровую графику

**Результат** — два взаимозаменяемых растровых оформления одной десктопной браузерной демки. Подготовить макеты состояний, нарезанные компоненты, спрайты, переходы, VFX и рабочую интеграцию. Ориентиры двух версий — Darkest Dungeon для `ink` и Hades для `myth`. Мир, персонажей, композиции и графику создавать для «Гнева глубин».

Начать с [контекста демки](gnev-glubin-demo-context.md). Открыть [актуальный HTML](https://chatgpt.com/library?file_id=libfile_da132154abf88191819c21f9d40dbc80&account_id=personal) или `poseidons-pond/index.html`. Основной формат макета — 1280 × 720 внутри игровой рамки. Отдельно проверить типичное окно 1440 × 900 и компактную ширину 720 px.

## 4. VFX и монтаж анимаций

Дать чистые прозрачные слои, отсчёт кадров слева направо и тайминг. Для однократных событий первый кадр сразу читается и быстро выходит к пику, затем эффект растворяется. Для петли начало и конец стыкуются без скачка. Начальная частота 8–12 fps для туши и 10–16 fps для динамичных эффектов. Размеры одного кадра приведены для интеграции, мастер можно хранить в 2×.

| Событие | Что подготовить | Встройка |
| --- | --- | --- |

| Смена камеры | 6–8 промежуточных кадров замаха, переходное размытие или всплеск, нейтральный кадр для склейки в обоих направлениях | Основная склейка уже управляет парковкой лодки, поз и рук. При интеграции синхронизировать `hero.cast` с `arms.cast` и `hero.land` с `effects.catch`. |

## 6. Экспорт и подключение

1. Внутри `poseidons-pond/` держать мастера и превью своего направления рядом с папкой исходников проекта, а экспорт для игры в `art/textures/<pack>/{scenes,map,actors,fish,fx,ui}/`. Имена файлов — латиницей в `kebab-case`. Крупные непрозрачные фоны — WebP. UI, спрайты и VFX — PNG или WebP с альфой. Прозрачные края должны сохранять цвет объекта без белой обводки. Всё игровое оформление экспортируется растром.
2. Подключить сцену, актёров и эффекты в `art/<pack>.js`. Для UI добавить правила только в `art/<pack>.css`, через `body[data-pack="<pack>"]`. Для CSS пути указывать относительно подпапки `art/`, например `url("textures/ink/ui/button-primary.png")`. Использовать общие DOM-контролы, CSS-состояния и действующие размеры хитбоксов. При необходимости уточнить селекторы в `ui.js`.
3. Для каждого спрайтового клипа дать равные кадры в горизонтальной полосе. Формат записи `{src, frames, fps, loop, tip, tips}`. Поля `tip` и `tips` относятся к рукам и задают одну точку или по одной точке на кадр. Для 2× сохранять те же координаты в пространстве 1280 × 720. У больших кадров хранить исходную нарезку и отдельно сжатый игровой экспорт.
4. Собрать автономный HTML через `node build.cjs`. Сборщик встраивает локальные растровые файлы из JS-манифестов и CSS. Проверить оба стиля в одном проходе, переключая их из настроек. Архив должен содержать исходники, готовые игровые растры, макеты PNG и перечень слотов, которые подключены.
5. Принимать по контрольным эпизодам: клик по обеим точкам карты, замок храма до ремонта, чистый сектор на фоне, бегущая риска, два рывка и подмотка, оба плавных перехода гнева и обратный переход, предупреждение об атаке поверх подсечки или вываживания, укладка, итог и лавка. На каждом экране проверить hover/focus/pressed, контраст текста и работу сборки без сети.
