# Две версии «Гнева глубин»

## Ветки и проверка изменений

`main` хранит общий пакет `packages/fishing` и проектную документацию. `game/3d` и `game/isometric` ответвляются от него и содержат свои запускаемые приложения. Изменение правила сначала коммитится в `main`, затем она вливается в обе игровые ветки. Изменение карты, рендера, управления или ассетов уходит PR в соответствующую игровую ветку. Для сравнения команда собирает два отдельных билда и проверяет один сценарий.

Для параллельного запуска в отдельных каталогах:

```sh
git worktree add ../gnev-3d game/3d
git worktree add ../gnev-iso game/isometric
```

| Слой | Содержимое |
| --- | --- |
| `packages/fishing` | Состояния заброса, поклёвки и вываживания, трюм, гнев, исход вылазки, экономика и таблица баланса. Правила выполняются без DOM и графического движка. |
| 3D | Трёхмерные камеры и сцены, GLB, водный шейдер, траектории и собственная навигация. |
| Изометрия | Двумерная карта столкновений, проекция на экран, Canvas 2D, спрайты и HUD. Вращение камеры отсутствует, масштаб подгоняется под окно. |

Сохранения имеют отдельные ключи. Для сравнительного плейтеста обеим сборкам выставляют один баланс, а прогресс начинают с чистого профиля.

## Как устроена изометрия

Карта задаёт контур воды, пирс, препятствия, рыбные места и декорации. Симуляция хранит две координаты. Проекция в пропорции 2:1 переводит их в Canvas, обратное преобразование переводит положение указателя в координаты заброса. Высота дуги поплавка и качка лодки рассчитываются для отрисовки. Глубину кадра дают отражения, контактные тени, ближние и дальние берега и сортировка спрайтов по экранному Y точки опоры. HUD получает состояние из игрового цикла, он не управляет временем вываживания.

## Производство спрайтов

1. Зафиксировать две рабочие карты и получить кадры с лодкой у ближнего и дальнего берега. На каждой карте проверить ширину фарватера, читаемость косяков и перекрытия при проходе у причала.
2. Готовить оригинальные спрайты в одном шаблоне ImageGen. Вид сверху под постоянным углом, свет слева сверху, выделенный контур, прозрачный фон, единый масштаб относительно лодки. Сохранять исходный лист и параметры нарезки. На первый проход нужны пирс обеих локаций, лодка с рыбаком, алтари, деревья, камни, бронзовый лик и эффекты воды.
3. Нарезать по альфе и закрепить точку опоры. Для дерева она у ствола, для лодки по ватерлинии. Габарит рисунка, точка опоры и коллизия задаются отдельно. Для лодки в следующем арт-проходе подготовить восемь ракурсов и короткие состояния гребли, заброса, вываживания. В текущем прототипе есть одна поза и зеркалирование.
4. Для спокойной воды, знамения и ярости оставить общую геометрию карты. Менять палитру и поведение брызг, волн и отражений. Проверять, что рыбные места и подсечка читаются на каждой стадии.
5. Хранить в Git оптимизированные игровые PNG/WebP и настройки размещения. Редактируемые исходники и подборки привязывать к задаче, крупные оригиналы хранить отдельно от игрового билда. При росте числа ассетов собрать атлас на локацию, предусмотреть 2–4 пикселя отступа и проверять альфу на светлом и тёмном фоне.
6. Повторить плейтест после каждой замены карты или пакета спрайтов. Проверить первую поимку, промах, заполнение трюма, возвращение с квотой и провал при полном гневе. Измерить частоту кадров на целевых устройствах перед выбором финального бюджета ассетов.

## Сборки для команды

GitHub Actions собирает каждую игровую ветку при пуше и изменении PR. В артефакт прогона попадает автономный HTML. Для публикации как сайта используется обычный `dist/` конкретной ветки. Два билда можно развернуть по разным адресам и закрепить в протоколе плейтеста вместе с хешами коммитов.
